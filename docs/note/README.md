## note に貼るときの手順

1. note で新規記事（テキスト）を作る
2. 1行目の `# 教室で使えるかもしれないもの作り #◯ …` をタイトル欄に入れる（本文には入れない）
3. 残りの本文を貼る。`##` の見出しは note がそのまま解釈し、目次も自動で作られます
4. 画像は貼りつけでは入らないので、`![...](images/xx.png)` の位置で `images/` の中の PNG を
   手動でアップロードする
5. 画像の直後の1行がキャプションです。note の画像キャプション欄に移してください
6. いちばん下の「🏷 ハッシュタグ」の見出しごと本文から外して、タグをハッシュタグ欄に入れる
7. 見出し画像（サムネイル）には `images/01-home.png` か `images/03c-memo-landscape.png` が
   おすすめです

本文には Markdown の表・太字・斜体を使っていません。貼るだけで崩れません。

**前の版を note に公開済みの場合は、貼り直しが要ります。** `giga-school.com/apps/qalc/` は
毎朝コミットから組み直されますが、note のほうは手で貼ったまま止まっているためです。

## 取材メモ

うかがった話です。記事に使った言いまわしのもとになっています。

**きっかけ。** 授業でタブレットを使い、クイズを使った学習サービス（カフート）を利用することが
とても多かった。使うと子どもたちは非常に熱狂的に学習に集中して取り組むことができた。
タブレットで計算問題を解き、そのポイントでクラスの友達と順位を競ったり、チームに分かれて
正解が多いほど有利になるゲームに協力して取り組んだりするサービス。

**引っかかっていた一点。** とても素晴らしい、魅力的なサービスである一方で、
ひとつだけ解決のしようがない部分があると感じていた。それが、4択クイズのように
4つの選択肢の中から答えを選ぶという回答方法だったこと。

**有料版に行かなかった理由。** 有料版では任意の回答方式を選べて、数字を実際に入力させる
問題も作れる。ただ、このサービスの良さは全国各地の先生たちが作った問題集を公開してくれていて、
学習に取り組んでいる単元について、こちらが準備をしなくてもインターネットで検索をすれば
優れた問題集が選び放題だったこと。何の準備もなく使える部分がとても助かるポイントだった。
4択じゃない問題を探すとなると有料プランに登録をするしかない。

**そこで作ったもの。** 自分で計算問題をひたすら楽しく解き続けられる Web アプリ。
子どもたちが熱狂する様子を見てきていたので、正解時の演出やタイムアタックモード、
サドンデスモードなどの多様な学習モード、協力ゲームや対戦ゲームなどの
マルチプレイヤーモードを実装した。

**特にこだわったところ。** 手書きで計算ができるメモパッド。簡単な計算問題だと暗算で
できてしまう部分もあるが、中学年以上の学習だと筆算をするような問題もたくさんある。
このときタブレットとノートを併用して筆算を書くという学習方法だと机が狭くてやりにくいので、
タブレットだけで完結ができるように、問題の横に大きく広く表示される手書きメモパッドを使って
筆算を書きながら計算問題に取り組めるようにした。これによって、簡単な計算問題だけでなく
複雑な計算問題もアプリの問題として成立させることができるようになった。

**使ってみた反応。** 実際に高学年のクラスでアプリを紹介して取り組んでもらったところ、
何度も繰り返し取り組んでくれた。「毎日楽しく学習しています」と伝えてくれる子がいた。
学力は決して高くない子でも楽しんで取り組んでくれているということがわかった。

## 文体の決まりを、今回だけ外したところ

`references/style.md` の D1 は「教室での出来事を実体験として書かない」と決めていて、
検査もそれを見ています。今回は、書き手ご本人が実際に見聞きした話であって嘘にならないため、
**書き手の判断でこの規則を外し、実体験として書いています。**

そのため lint の `✗` が1件だけ残ります。

```
✗  7  [事実] 自分の教室で起きたこととして書いている  私のクラス
```

該当するのは「🏫 はじめに」の2段落目、「私のクラスでもよく使っていました。」の一文です。
検査の側を通したくなった場合は、この一文を
「教室で使っていると、ふだんは計算の時間に机に伏せてしまう子まで、身を乗り出して
画面を見ています。」のように書きかえれば `✗` は消えます。ただし記事の説得力は落ちます。

「✨ 導入のメリット」の三つ目に入れた高学年クラスの話は、検査の網には掛かっていませんが、
同じ判断で入れたものです。外す場合はその段落ごと落としてください。

## スクリーンショットの撮りかた（撮り直すとき）

すべて実際にビルドしたアプリを実ブラウザ（Chromium）で操作して撮っています。合成・加工はしていません。
手書きメモの筆算も、画面に出た問題を読み取って、ポインタ操作で本当に書いたものです。

```bash
npm i --no-save playwright peer
npm run build
node .claude/skills/note-article/scripts/serve.mjs dist 4180 /
node .claude/skills/note-article/scripts/capture.mjs .tmp-shots/shots.mjs \
  --base http://127.0.0.1:4180/ --out docs/note/images
```

画面の大きさは 390×844 を基本に、ホームとコース管理だけ 390×1900、ショップは 390×940、
てがきメモの縦は 390×1180、横は 1024×768 です（`deviceScaleFactor: 2`）。

踏んだところを3つだけ残しておきます。次に撮る人が同じところで止まらないように。

- **ホーム画面は、一度あそんでから撮ること。** まっさらな状態だと連続学習日数も
  まなびのきろくも出ず、本文の説明と写っているものが食いちがいます。今回は先に10問解いて、
  最初の2問はわざとまちがえてから撮っています。「もういちどやってみよう」に問題が並ぶのは
  そのためです
- **テンキーとペンのボタンは `el.click()` では反応しません。** framer-motion のボタンなので、
  Playwright の実マウス（`page.mouse.click`）で押す必要があります
- **`document.querySelector('canvas')` で手書きの領域を取らないこと。** 紙ふぶきも canvas を
  置いていくので取りちがえます。`canvas.touch-none` で、位置が `fixed` でないものを選びます

みんなであそぶの画面（`11`〜`18`）を撮り直すときは、前回と同じく
`0.peerjs.com` に出られないため、シグナリングサーバをローカルに立てて `PEER_OPTIONS` の
接続先を差しかえる必要があります。手順は `.claude/skills/note-article/scripts/peer-server.mjs`
の先頭にあります。差しかえたら撮影後に必ず戻してください。

## 撮影中に気づいた、記事とは別の話

記事の内容には影響しませんが、踏んだので残しておきます。直すなら記事とは別のコミットで。

1. **結果画面でコンソールにエラーが1件出ます。**
   `Refused to create a worker from 'blob:...' because it violates the following
   Content Security Policy directive: "worker-src 'self'"`。
   `canvas-confetti` が紙ふぶきの計算を Web Worker に逃がそうとして、`index.html` の CSP に
   はじかれています。canvas-confetti はこの失敗を受け取ると主スレッドで動く作りなので、
   **紙ふぶきそのものは出ています**（撮影中も canvas が作られていました）。
   消すなら `worker-src 'self' blob:` を足すか、`triggerConfetti` に `useWorker: false` を渡します
2. **てがきメモのペンのボタンに読み上げ用の名前が付いていません。**
   となりの電球には `aria-label="かんがえるどうぐ"` があるのに、ペンのボタン
   （`src/App.jsx` の `lucide-pen-tool` のほう）には `aria-label` がありません。
   ふりがなやコントラストまで気を配っているアプリなので、ここだけ抜けているのは惜しいです
3. **`README.md` と `MANUAL.md` に、記録の写しの記述がありません。**
   記事には書きましたが、先生向けの手引きにも一行あると、問い合わせを受けたときに困りません
